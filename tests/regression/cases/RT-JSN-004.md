## Цель

Регрессия #38: торможение при раскрытии JSON.

## Проверяемые требования

- `REQ-JSN-06` — Производительность раскрытия больших и глубоких JSON (#38).
- `REQ-BIG-01` — Строки длиннее BigLineSize (по умолчанию 4096 в регрессионной конфигурации) обрезаются (`Truncate`, многоточие `...`) или переносятся (`Wrap`) по BigLineSize символов.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Settings → View: Big line handling = `Wrap`, Big line size = `100000`, Save. Открыть `json-xml.log`. | Строка `[J05]` (≈65 тыс. символов) не обрезается. |
| 2 | Раскрыть JSON `[J05]`, засечь время. | Раскрытие ≤ 2 с, UI не зависает; прокрутка раскрытого блока плавная. |
| 3 | Свернуть и снова раскрыть `[J05]` 5 раз подряд. | Каждое раскрытие ≤ 1 с, память процесса (Диспетчер задач) не растёт неограниченно. |
| 4 | Раскрыть `[J06]` (вложенность 60 уровней) через `Expand recursively`. | Все уровни `l59`…`l0` отображаются, без StackOverflow/аварии. |
| 5 | Вернуть Big line size = `4096`, Big line handling = `Truncate`, Save. Проверить `[J05]`. | Строка обрезана до 4096 символов с `...`, раскрытие не вызывает ошибок. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- Вернуть `BigLine: prune`, `BigLineSize: 4096`.
- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
