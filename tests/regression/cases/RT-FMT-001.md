## Цель

Проверить разбор строк по формату и формирование колонок.

## Проверяемые требования

- `REQ-FMT-01` — Формат лога описывается регулярным выражением с именованными группами; поля становятся колонками.
- `REQ-IDX-01` — Поля из IndexedFields доступны как фильтруемые колонки с перечнем значений.
- `REQ-IDX-02` — Неиндексируемые поля отображаются как колонки, но без фильтра значений.
- `REQ-FMT-06` — Синтаксис групп `(?<Name>…)` и `(?'Name'…)` поддерживается одинаково.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `tab-basic.log` (профиль Classic). | Колонки: `Time`, `Thread`, `Severity`, `Component`, `Message` (формат 2 профиля Classic, группы вида `(?'Name'…)`). |
| 2 | Проверить строку `[T05]`. | Time `10:00:01.000`, Thread `0x0A02`, Severity `ERR`, Component `Db`, Message `[T05] query failed step=2 code=0x80070005`. |
| 3 | Навести курсор на заголовки колонок `Thread`, `Severity`, `Component`. | У индексируемых колонок есть кнопка фильтра (`Filter column`). |
| 4 | Навести курсор на заголовки `Time` и `Message`. | Кнопки фильтра нет (поля не индексируются). |
| 5 | Открыть `classic-multiline.log`. | Колонки `Time`, `Level`, `Thread`, `Component`, `Message` (формат 1, группы `(?<Name>…)`). |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.
