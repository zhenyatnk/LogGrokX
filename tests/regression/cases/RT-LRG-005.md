## Цель

Проверить удержание открытого файла (блокировку переименования/удаления) и работу с уже прочитанными данными.

## Проверяемые требования

- `REQ-LRG-06` — Открытый документ удерживает файл: переименование/удаление на диске до закрытия вкладки отклоняется (`IOException`), приложение продолжает работать с уже прочитанными данными и не падает; после закрытия вкладки файл освобождается (#126).

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Скопировать `search.log` в `$env:TEMP\lgx-del.log`, открыть его. | 19 строк. |
| 2 | Выполнить `Rename-Item $env:TEMP\lgx-del.log lgx-del2.log`. | Переименование отклонено: `IOException` (файл занят процессом LogGrokX). Приложение не падает, документ `lgx-del.log` остаётся открытым. |
| 3 | Прокрутить документ, выполнить поиск `alpha`, скопировать строку. | Работа с уже прочитанными данными продолжается; аварии и диалогов ошибок нет. |
| 4 | Закрыть вкладку `lgx-del.log`, затем выполнить `Rename-Item $env:TEMP\lgx-del.log lgx-del2.log` и `Remove-Item $env:TEMP\lgx-del2.log`. | После закрытия вкладки файл освобождён: переименование и удаление выполняются без ошибок. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Краевые случаи и примечания

- Открытый файл удерживается намеренно: чтение изменяемого лога без блокировки приводило бы к ошибкам (#126).

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- Удалить временные файлы, если остались.
- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
