## Цель

Регрессия #77: PEM/сертификаты в JSON раскрываются по полям.

## Проверяемые требования

- `REQ-B64-07` — Base64/PEM внутри JSON и XML декодируются с сохранением валидности; ключи JSON не декодируются; PEM в JSON раскрывается в JSON-объект по полям (#77).

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `binary\binary.log`, `BIN` у `[B19]`. | `token` стал объектом `{"alg":"HS256","typ":"JWT","ser":"empty"}`, `n`=1; ключ `eyJpZCI6NDIsIm9rIjp0cnVlfQ` НЕ декодирован; JSON сворачивается. |
| 2 | `BIN` у `[B20]` (экранированные `\u002B`, `\/`). | Значение `v` = `~~~>>>???<<<~~~ value`. |
| 3 | `BIN` у `[B21]` (XML). | Текст `a`, атрибут `attr` и CDATA `c` = `a < b & c "quoted"`, в разметке экранировано (`&lt;`, `&amp;`, `&quot;`); XML остаётся валидным и сворачивается. |
| 4 | `BIN` у `[B23]` (JSON с сертификатами и blob). | `cert` раскрыт в JSON-объект по полям (`Subject`, `Issuer`, `Serial number`, …), `two` — два сертификата, `blob` — описание ключа; JSON сворачивается по полям. |
| 5 | `BIN` у `[B12]`. | Аналогично: сертификат как JSON-объект по полям. |

## Критерии прохождения

- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.
