## Цель

Проверить поставляемые профили Venn и Plain text.

## Проверяемые требования

- `REQ-FMT-01` — Формат лога описывается регулярным выражением с именованными группами; поля становятся колонками.
- `REQ-FMT-02` — Автоопределение формата по первым строкам файла (до 256 строк / 1 МБ): выбирается формат с наибольшей долей совпадений.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `formats\venn.log` в профиле `Classic`. | Строки подходят под формат 1 Classic (Time `2026-05-14 9:05:01.123`, Level `-`, Thread `[INFO]` и т.д.) — это ожидаемое следствие порядка форматов; фиксируется как наблюдение. |
| 2 | Переключить профиль на `Venn`. | Колонки Venn: Time, Level, Context/Sid/Pid/Thread, Process, Source, Irql, Message (по фактическому набору групп). Все 5 строк `[V01]`–`[V05]` разобраны, загрузка завершена (#113). Строка `[V04]`: Level `CRIT`, Irql `2`; строка `[V05]`: Source `Core`, без Process. |
| 3 | Проверить цвета Venn. | `[V04]` (CRIT) — фон `#FFCD5C5C`; `[V02]` (ERRO) — красный текст; `[V03]` (WARN) — Chocolate; `[V05]` (TRAC) — серый. |
| 4 | Переключить профиль на `Plain text`. | Одна колонка `Text` с целой строкой, без цветов. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Артефакты для отчёта

- Вернуть профиль `Classic`.

- Восстановить исходную конфигурацию, если она менялась (см. README).
