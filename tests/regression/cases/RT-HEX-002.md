## Цель

Регрессия #75 (HEX→PEM) и #77.

## Проверяемые требования

- `REQ-HEX-03` — HEX в JSON/XML декодируется с экранированием; HEX, дающий JSON/XML, форматируется.
- `REQ-HEX-04` — HEX-кодированные DER/PEM сертификаты показываются как сводка (#75); Decode HEX в контекстном меню.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `hex.log`, BIN у `[H08]`. | `payload` = `Hello \"world\"\n` (экранировано, JSON валиден и сворачивается); ключ `48656C6C6F20776F726C64` не декодирован. |
| 2 | BIN у `[H09]`. | `<v>&lt;tag&gt; &amp; more</v>`, `attr="x &lt; y &amp; z"`; XML сворачивается. |
| 3 | BIN у `[H10]`. | Отформатированный JSON `{"hex":true,"n":5}`. |
| 4 | BIN у `[H11]` (HEX DER). | Сводка сертификата, совпадает с `EXPECTED.md`. |
| 5 | BIN у `[H12]` (HEX → PEM). | Маркеры PEM и сводка сертификата. |
| 6 | BIN у `[H13]`. | `cert` раскрыт как JSON-объект по полям сертификата. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.
