# RT-LCH-004. Несуществующий путь в командной строке игнорируется

| Поле | Значение |
|---|---|
| ID | `RT-LCH-004` |
| Область | LCH — Запуск и единственный экземпляр |
| Приоритет | P2 |
| Тип | Негативный |
| Требования | `REQ-LCH-04` |
| Профиль | `Classic` |
| Конфигурация | `testdata/config/appsettings.regression.yaml` |
| Данные | `%RT%\testdata\tab-basic.log` |
| Ориентировочная длительность | 5 мин |
| Дефекты (регрессия) | — |
| Внешние ресурсы / ручные действия | Нет |

## Цель

Проверить устойчивость к неверным путям.

## Проверяемые требования

- `REQ-LCH-04` — Несуществующий путь в командной строке / при открытии игнорируется без аварии.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Закрыть LogGrokX. Выполнить `& "%APP%\LogGrokX.exe" C:\nonexistent\missing.log "%RT%\testdata\tab-basic.log"`. | Приложение запускается, открыта только вкладка `tab-basic.log`; диалогов об ошибке и аварии нет. |
| 2 | Выполнить `& "%APP%\LogGrokX.exe" C:\nonexistent\only-missing.log` при уже запущенном приложении. | Новых вкладок не появилось, первое окно продолжает работать, второго окна нет. |
| 3 | Открыть `%LOCALAPPDATA%\LogGrokX\` и найти свежий диагностический лог. | В логе есть запись об отсутствующем файле (`File ... is not exists`). Отсутствие записи — не FAIL, а замечание S4. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
