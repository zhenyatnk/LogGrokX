## Цель

Проверить устойчивость к блокировкам файла.

## Проверяемые требования

- `REQ-LRG-04` — Файл, заблокированный эксклюзивно, не приводит к аварии приложения.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Скопировать `tab-basic.log` в `$env:TEMP\lgx-locked.log`. В отдельной консоли: `& "%RT%\tools\Lock-LogFile.ps1" -Path $env:TEMP\lgx-locked.log -Share None`. | Выведено `LOCKED (None)`. |
| 2 | Открыть `$env:TEMP\lgx-locked.log` через Ctrl+O. | Приложение НЕ завершается аварийно. Допустимо: сообщение об ошибке или отсутствие документа. Авария/необработанное исключение — FAIL S2. |
| 3 | Освободить файл (Enter в консоли блокировки) и открыть его снова. | Файл открывается, 16 строк. |
| 4 | Повторить шаг 1 с `-Share Read` и открыть файл. | Открытие с FileShare.Read со стороны держателя → LogGrokX (FileAccess.Read, FileShare.ReadWrite) может получить ошибку совместного доступа; ожидание то же: без аварии. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Краевые случаи и примечания

- По коду `AddDocument` перехватывает только FormatException/ArgumentException; IOException может привести к аварии — именно это проверяет кейс.

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- `Remove-Item $env:TEMP\lgx-locked.log`
- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
