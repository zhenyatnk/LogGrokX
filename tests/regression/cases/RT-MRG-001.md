## Цель

Проверить объединённый просмотр.

## Проверяемые требования

- `REQ-MRG-01` — Merged files view (View) объединяет все открытые документы по времени; колонки выравниваются без учёта регистра; Level/Severity → Severity.
- `REQ-MRG-02` — Порядок: по времени; при равном времени — по порядку источника, затем по номеру строки; источники без времени или с немонотонным временем — в конце; простой текст → Message.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).
- Активный профиль: `Regression`.

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Профиль `Regression`. Открыть по порядку `merge\merge-a.log`, затем `merge\merge-b.log`. View → Merged files view. | Вкладка `Merged files`; 24 строки. |
| 2 | Проверить колонки. | `Time`/`time`, `Thread`/`thread`, `Component`/`component` объединены (без учёта регистра); `Level` (A) и `Severity` (B) — одна колонка `Severity`. |
| 3 | Проверить порядок. | `A01, B01, A02, B02, …, A11, A12, B11, B12`: при равном времени 10:00:02.200 `A12` (источник 1) раньше `B11`. |
| 4 | Строки подкрашены по источнику; на таймлайне цвета источников. | Подкраска разная для A и B. |
| 5 | Открыть дополнительно `merge\merge-plain.txt` и `merge\merge-unordered.log`. | Объединение пересчитано: строки без времени (`plain merged line 1–5`, текст в Message) и немонотонного источника (`Z01`–`Z05`) — в конце после упорядоченных. |
| 6 | Перезапустить приложение. | Режим объединения не восстановлен (только на сессию). |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
