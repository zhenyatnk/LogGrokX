## Цель

Регрессия #111: JSON-массивы `[...]` распознаются целиком и сворачиваются; квадратные скобки обычного текста и массивы из одного элемента верхнего уровня не превращаются в JSON.

## Проверяемые требования

- `REQ-JSN-10` — JSON-массивы `[...]` (примитивы, объекты, вложенные массивы) распознаются целиком и по умолчанию свёрнуты, как и объекты, независимо от размера; текст в квадратных скобках, который не является валидным JSON, остаётся обычным текстом (#111); массив из одного элемента верхнего уровня не сворачивается: `[3]` — обычный текст, у `[{…}]` сворачивается только объект; массивы внутри JSON не меняются.
- `REQ-JSN-05` — Некорректный JSON отображается как текст без аварии; текст до и после JSON сохраняется; несколько JSON в строке.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Краевые случаи и примечания

- Распознавание массивов добавлено в #145 (`GetBracketedGroups`). Массив из одного элемента верхнего уровня (`[3]`, `["abc"]`) не сворачивается, сворачиваемый элемент внутри него сворачивается сам (#153); шаги 6–10 проверяют ложные срабатывания.
- Сравнение с RT-JSN-001: там массив `[J02]` проверяется на исходных данных, здесь — массивы примитивов, вложенные и пустые.
