## Цель

Проверить граничные варианты содержимого файла.

## Проверяемые требования

- `REQ-ENC-03` — Пустой файл и файл только из пустых строк открываются без ошибок.
- `REQ-ENC-04` — Двоичный (не текстовый) файл открывается без аварии.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `encoding\empty.log` (0 байт). | Вкладка открыта, вместо сетки показана страница `This file is empty` с описанием и кнопкой `Open log file`; лишней пустой записи и строки таймлайна нет, ошибок нет. |
| 2 | В пустом документе нажать `Ctrl+F`, ввести `a`; нажать `F3`, `Shift+F3`, `Ctrl+A`, `Ctrl+C`. | Нет аварий; `0 matches` (или пустой счётчик). |
| 3 | Открыть `encoding\only-newlines.log` (10 × CRLF). | Документ открыт, видны пустые строки (или 0 записей), без ошибок. |
| 4 | Открыть `encoding\binary.bin` (64 КБ двоичных данных). | Документ открыт в текстовом режиме, приложение отзывчиво, нет аварии. |
| 5 | Прокрутить `binary.bin` до конца, выполнить поиск `\x00` с regex. | Нет зависаний > 5 с и нет исключений. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.
