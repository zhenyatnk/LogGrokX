## Цель

Проверить обрезку больших строк.

## Проверяемые требования

- `REQ-BIG-01` — Строки длиннее BigLineSize (по умолчанию 4096 в регрессионной конфигурации) обрезаются (`Truncate`, многоточие `...`) или переносятся (`Wrap`) по BigLineSize символов.
- `REQ-BIG-02` — Строки длиной ≤ BigLineSize отображаются полностью; копирование возвращает исходный полный текст.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Убедиться: Settings → View → Big line handling = `Truncate`, Big line size = `4096`. Открыть `biglines.log`. | 6 записей `[L01]`–`[L06]`; длина Message = значению `size=`. |
| 2 | Проверить `[L01]` (100), `[L02]` (4095), `[L03]` (4096). | Отображаются полностью, в конце видны `END1`, `END2`, `END3`. |
| 3 | Проверить `[L04]` (4097), `[L05]` (10000), `[L06]` (100000). | Обрезаны до 4096 символов и оканчиваются `...`; `END4`/`END5`/`END6` не видны. |
| 4 | Выделить `[L06]`, `Ctrl+C`, `(Get-Clipboard -Raw).Length`. | Скопирован полный текст строки (≈100 000 символов в Message, оканчивается `END6`, без `...`). |
| 5 | Искать `END6`. | 1 совпадение `[L06]`. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.
