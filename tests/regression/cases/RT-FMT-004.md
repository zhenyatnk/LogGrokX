| Ориентировочная длительность | 5 мин |
| Дефекты (регрессия) | — |

## Цель

Проверить правило выбора при равной доле совпадений.

## Проверяемые требования

- `REQ-FMT-04` — При равной доле совпадений выбирается формат, стоящий раньше в списке.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `formats\ambiguous-tab.log` (подходит под форматы 2 и 4 Classic). | Используется формат 2: колонка `Component` содержит `Comp` (без завершающего табулятора), Message — `[F01] ambiguous`. |
| 2 | В Settings → Profiles → Log formats профиля Classic переставить формат 4 («LogGrokX logs») выше формата 2 (если перестановка поддерживается) и сохранить; переоткрыть файл. | Теперь используется ранее четвёртый формат (значение Component может содержать завершающий `\t`). Если перестановка в UI не поддерживается — изменить порядок в YAML, кейс помечается как выполненный через YAML. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- Восстановить `appsettings.yaml` из эталона `appsettings.regression.yaml`.
- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
