# RT-SRCH-001. Базовый поиск, счётчик и Match case

| Дефекты (регрессия) | — |

## Цель

Проверить базовый поиск.

## Проверяемые требования

- `REQ-SRCH-01` — Поиск по подстроке без учёта регистра по умолчанию; запуск через ~0,5 с после ввода; счётчик `{N} matches` и позиция `{i} of {N}`.
- `REQ-SRCH-02` — Переключатель Match case.
- `REQ-SRCH-04` — Список результатов поиска с разобранными полями; выбор результата переходит к строке в сетке.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `search.log`. `Ctrl+F`, ввести `payment failed`. | Через ~0,5 с найдено 3 совпадения (`[S09]`, `[S10]`, `[S11]`), счётчик `3 matches`; список результатов показывает строки с полями Time/Level/Thread/Component/Message. |
| 2 | Включить `Match case`. | Остаётся 1 совпадение `[S10]` (`payment failed`). |
| 3 | Изменить текст на `FAILED`. | 1 совпадение `[S09]`. |
| 4 | Выключить `Match case`, кликнуть второй результат в списке. | Сетка переходит к строке `[S10]`, строка выделена и центрирована, позиция `2 of 3`. |
| 5 | Ввести `Ошибка`, затем включить Match case. | Без Match case — 2 (`[S12]`, `[S13]`); с Match case — 1 (`[S12]`). |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.
