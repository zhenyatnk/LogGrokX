## Цель

Проверить совместный доступ к активно пишущемуся логу.

## Проверяемые требования

- `REQ-LRG-03` — Файл, открытый другим процессом на запись (FileShare.ReadWrite/Read), открывается для чтения.
- `REQ-LRG-05` — Изменение файла после открытия (дописывание) не ломает отображение уже прочитанной части.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | В отдельной консоли запустить `& "%RT%\tools\Start-LogAppender.ps1" -Path $env:TEMP\lgx-grow.log -Count 60 -IntervalMs 1000 -Truncate`. | Скрипт начинает писать строки `[G-001]`… |
| 2 | Через ~5 с открыть `$env:TEMP\lgx-grow.log` в LogGrokX. | Файл открывается без ошибок совместного доступа; видны уже записанные строки. |
| 3 | Подождать 10 с, наблюдая за сеткой. | Приложение не падает. Зафиксировать: появляются ли новые строки автоматически (ожидание по текущей реализации — НЕТ, файл читается до размера на момент открытия). |
| 4 | Закрыть и заново открыть документ. | Отображаются все записанные к этому моменту строки. |
| 5 | Дождаться окончания скрипта. | Скрипт завершился без ошибок записи (LogGrokX не блокирует запись). |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Краевые случаи и примечания

- Отсутствие автодобавления строк — ожидаемое поведение (tail не реализован), не FAIL.

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- `Remove-Item $env:TEMP\lgx-grow.log`
- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
