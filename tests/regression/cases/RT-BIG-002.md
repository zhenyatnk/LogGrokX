## Цель

Проверить режим Wrap и валидацию.

## Проверяемые требования

- `REQ-BIG-01` — Строки длиннее BigLineSize (по умолчанию 4096 в регрессионной конфигурации) обрезаются (`Truncate`, многоточие `...`) или переносятся (`Wrap`) по BigLineSize символов.
- `REQ-BIG-03` — Валидация BigLineSize: `Big line size must be a positive integer.`; изменение применяется после сохранения.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Settings → View → Big line handling = `Wrap`, Save. Открыть `biglines.log`. | `[L03]` (4096) — одна визуальная строка; `[L04]` — 2 строки (4096 + 1 символ); `[L05]` — 3 строки (4096, 4096, 1808); `[L06]` — 25 строк; `END4`–`END6` видны. |
| 2 | Big line size = `0`. | Ошибка `Big line size must be a positive integer.`, Save недоступна/предлагает автоисправление. |
| 3 | Big line size = `-5`, затем `abc`, затем пусто. | Та же ошибка во всех случаях. |
| 4 | Big line size = `5000`, Save. | `[L05]` переносится по 5000 (2 строки); `[L04]` целиком. |
| 5 | Вернуть `Truncate` и `4096`, Save. | Поведение как в RT-BIG-001. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.
