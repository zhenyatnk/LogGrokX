# RT-LCH-008. Штатное завершение без Fail Fast и с кодом 0

| Поле | Значение |
|---|---|
| ID | `RT-LCH-008` |
| Область | LCH — Запуск и единственный экземпляр |
| Приоритет | P1 |
| Тип | Регрессия дефекта |
| Требования | `REQ-LCH-09` |
| Профиль | `Classic` |
| Конфигурация | `testdata/config/appsettings.regression.yaml` |
| Данные | — |
| Ориентировочная длительность | 10 мин |
| Дефекты (регрессия) | [#131](https://github.com/zhenyatnk/LogGrokX/issues/131) |
| Внешние ресурсы / ручные действия | Нет |

## Цель

Регрессия #131: при выходе на Windows 10 оставался управляемый хук AvalonDock (`WH_CBT`), и процесс завершался Fail Fast `0xC0000602`, потому что `App.OnExit` не вызывал `base.OnExit`.

## Проверяемые требования

- `REQ-LCH-09` — Штатное закрытие (крестик, Alt+F4, в том числе во время загрузки) завершает процесс с кодом 0, без диалога Fail Fast и событий WER (#131).

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).
- Кейс обязателен на Windows 10 22H2; на Windows 11 выполняется как дополнительная проверка (дефект воспроизводился на Windows 10).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Закрыть все экземпляры. В PowerShell: `$p = Start-Process "%APP%\LogGrokX.exe" -ArgumentList '"%RT%\testdata\tab-basic.log"' -PassThru`. | Открыто окно с документом `tab-basic.log`. |
| 2 | Набрать текст в поле поиска (активирует TSF/IME), открыть и закрыть Settings, перетащить вкладку в плавающее окно и вернуть обратно. | Действия выполнены без ошибок; задействованы хуки AvalonDock и окна ввода текста. |
| 3 | Закрыть главное окно крестиком. `$p.WaitForExit(15000); $p.ExitCode`. | Процесс завершился за ≤ 15 с с кодом `0`. Нет диалога `Fail Fast Exception` / `SystemResourceNotifyWindow`, нет кода `0xC0000602` (`-1073740286`). |
| 4 | `Get-WinEvent -FilterHashtable @{LogName='Application'; ProviderName='Application Error','Windows Error Reporting','.NET Runtime'; StartTime=(Get-Date).AddMinutes(-5)} -ErrorAction SilentlyContinue \| ? Message -match 'LogGrokX'`. | Событий об аварии LogGrokX нет. |
| 5 | Повторить шаги 1–4, закрыв приложение через `Alt+F4`, а затем — открыв большой файл (`New-LargeLog.ps1 -Path $env:TEMP\lgx-large.log -SizeMB 256`) и закрыв окно до окончания загрузки. | Во всех вариантах код выхода `0`, диалогов и событий WER нет. |
| 6 | Повторить шаги 1–4, дополнительно открыв `search.log`, объединённый просмотр (View → Merged files view) и пометив строку в Marked lines. | Код выхода `0`, аварии нет. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Краевые случаи и примечания

- Проверять установленную (setup) и self-contained сборки: дефект был обнаружен на установленной 1.7.6.
- Если на стенде отключён WER, достаточно кода выхода и отсутствия диалога; указать это в отчёте.

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- `Remove-Item $env:TEMP\lgx-large.log -ErrorAction SilentlyContinue`
- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
