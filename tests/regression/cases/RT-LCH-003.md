## Цель

Проверить разрешение относительных путей и поддержку пробелов/Unicode в путях.

## Проверяемые требования

- `REQ-LCH-03` — Относительные пути командной строки разрешаются относительно текущего каталога.
- `REQ-DOC-07` — Пути с пробелами и не-ASCII символами открываются корректно, имя вкладки отображается полностью/сокращённо без искажений.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Закрыть LogGrokX. `Set-Location "%RT%\testdata\encoding"`; выполнить `& "%APP%\LogGrokX.exe" ".\путь с пробелами\лог файл.log" ..\tab-basic.log`. | Открыты две вкладки: `лог файл.log` и `tab-basic.log`. Имя с пробелами и кириллицей отображается без искажений. |
| 2 | В контекстном меню вкладки `лог файл.log` выбрать `Copy Full Path`; вывести буфер обмена `Get-Clipboard`. | В буфере полный абсолютный путь `...\testdata\encoding\путь с пробелами\лог файл.log` (без `.\`). |
| 3 | Проверить содержимое документа `лог файл.log`. | 5 строк `[E01]`…`[E05]`, текст `Кириллица и ümlaut №N` отображается корректно. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Артефакты для отчёта

- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
