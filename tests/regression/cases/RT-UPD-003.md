## Цель

Регрессия #99: индикатор новой версии в заголовке.

## Проверяемые требования

- `REQ-UPD-03` — Индикатор в заголовке: `Update to {0}`, `Downloading {0:0}%`, `Restart: {0}`; скрывается настройкой Update indicator in title bar (#99).
- `REQ-UPD-05` — Портативная сборка не обновляется сама — открывает страницу релиза; проверка через системный прокси с учётными данными Windows (#29).
- `REQ-UPD-04` — Update: загрузка установщика текущей архитектуры с проверкой SHA256SUMS.txt; Restart сохраняет открытые файлы и открывает их после установки; тихая установка при выходе; What's new после обновления.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Предыдущая версия, режим `Install updates automatically`. | Без диалога: индикатор `Downloading {0:0}%` → `Restart: {0}`; `LogGrokX {0} will be installed silently when you close the application.` |
| 2 | Settings → View → выключить `Update indicator in title bar`. | Индикатор скрыт, загрузка/установка продолжается. |
| 3 | Обычный выход из приложения. | Тихая установка после выхода; при следующем запуске `What's new`. |
| 4 | Портативная сборка предыдущей версии (zip), режим check. | Диалог/индикатор предлагает `Open release page`/`Open download page`; самообновление не выполняется. |
| 5 | Локальная сборка (`dotnet build`, версия 0.0). | Проверка не приводит к аварии; поведение зафиксировать. |
| 6 | Отключить сеть, Support → Check for updates. | `Update check failed: …` без аварии. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.
