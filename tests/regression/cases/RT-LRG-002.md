## Цель

Проверить производительность поиска/фильтров на больших данных.

## Проверяемые требования

- `REQ-LRG-02` — Поиск и фильтрация работают на большом файле и могут быть прерваны/изменены во время выполнения.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Открыть `$env:TEMP\lgx-large.log` (из RT-LRG-001) и дождаться загрузки. | Файл загружен. |
| 2 | Выполнить поиск `L-MID`. | Найдено ровно 1 совпадение; прогресс поиска виден; переход по `F3` центрирует строку `[L-MID]`. |
| 3 | Запустить поиск `L-ERR` и, не дожидаясь окончания, заменить текст на `L-LAST`. | Предыдущий поиск прекращён, итог: 1 совпадение `[L-LAST]`; нет «зависших» результатов `L-ERR`. |
| 4 | Исключить значение `Thread-01` в колонке `Thread` (контекстное меню ячейки → `Exclude`). | Фильтр применяется без зависания UI; строки `Thread-01` скрыты; появился чип `Thread: Thread-01`. |
| 5 | Удалить чип фильтра. | Все строки снова видны. |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- `Remove-Item $env:TEMP\lgx-large.log`
- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
