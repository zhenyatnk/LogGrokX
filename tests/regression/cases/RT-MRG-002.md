## Цель

Проверить функции в объединённом виде.

## Проверяемые требования

- `REQ-MRG-03` — В объединённом виде работают поиск, фильтр времени, группировка, JSON, метки; строки подкрашены по источнику; режим только на сессию.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).
- Активный профиль: `Regression`.

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | В объединённом виде из RT-MRG-001 (A и B) искать `event 1` (обычный текст). | Совпадения из обоих источников (`A01`, `A10`, `A11`, `B01`, `B10`, `B11`, `B12`). |
| 2 | F3/Shift+F3. | Навигация по объединённому порядку. |
| 3 | Включить `Use Regular Expressions`, искать `event 1$`. | Ровно 2 совпадения: `A01` и `B01` (строки с CRLF): якорь `$` срабатывает перед концом строки и в объединённом просмотре, `A10`, `A11`, `B10`–`B12` не найдены (PR #133). |
| 4 | Выключить `Use Regular Expressions`, очистить поиск. | Исходное состояние поиска. |
| 5 | Таймлайн: выбрать 10:00:01.000–10:00:01.500. | Видны `B05` (1.000), `A06` (1.100), `B06`, `A07`, `B07`, `A08` (1.500) — с учётом включённых границ; строки вне диапазона скрыты. |
| 6 | Фильтр Severity: исключить `INFO`. | Только `A05` (ERROR) и `B03` (WARN). |
| 7 | Пометить `B03`. | Метка видна в Marked lines (группа merge-b.log) и в исходном документе. |
| 8 | Group by thread. | Группировка по Thread в пределах источника. |
| 9 | Закрыть merge-b.log. | Объединение пересчитано без ошибок (`Could not refresh the merged view. Try again.` не появляется). |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.
