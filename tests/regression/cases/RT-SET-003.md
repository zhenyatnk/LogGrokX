| Поле | Значение |
|---|---|
| ID | `RT-SET-003` |
| Область | SET — Настройки |

| Тип | Негативный |
| Требования | `REQ-SET-03` |
| Профиль | `Classic` |
| Конфигурация | `testdata/config/appsettings.malformed.yaml` |
| Данные | — |
| Ориентировочная длительность | 5 мин |
| Дефекты (регрессия) | — |
| Внешние ресурсы / ручные действия | Нет |

## Цель

Проверить устойчивость к битому YAML.

## Проверяемые требования

- `REQ-SET-03` — Некорректный YAML не приводит к аварии: приложение запускается/продолжает работу с последней корректной конфигурацией и сообщает об ошибке.

## Предусловия

- Выполнена базовая подготовка окружения из [README](../README.md#подготовка-окружения) (конфигурация, чистые данные пользователя).

## Шаги

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | При запущенном приложении заменить `%APP%\appsettings.yaml` на `appsettings.malformed.yaml`. | Приложение не падает, продолжает работать с прежней конфигурацией; ошибка записана в лог `%LOCALAPPDATA%\LogGrokX\` или показана пользователю. |
| 2 | Закрыть приложение и запустить с некорректным YAML. | Запуск без аварии (значения по умолчанию или сообщение об ошибке); зафиксировать поведение в отчёте. |
| 3 | Восстановить `appsettings.regression.yaml`. | Конфигурация применяется (горячая перезагрузка). |

## Критерии прохождения

- Фактический результат каждого шага совпадает с ожидаемым.
- Нет аварийного завершения, зависаний UI > 5 с и необработанных исключений в логе `%LOCALAPPDATA%\LogGrokX\`.

## Артефакты для отчёта

- Скриншот после каждого шага с проверкой UI (`step-NN.png`).
- Содержимое буфера обмена/файлов для шагов с копированием и сохранением.

## Очистка

- Восстановить `appsettings.regression.yaml`.
- Закрыть открытые документы.
- Восстановить исходную конфигурацию, если она менялась (см. README).
